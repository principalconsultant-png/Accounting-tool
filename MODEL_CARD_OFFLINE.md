# Riju offline intent model v1 — B22

This is a small statistical topic classifier with deterministic entity extraction and posting validation. It is not a generative LLM, chatbot or general financial adviser. No network service, external model download, GPU, native inference package, or customer-data training is used. Python standard-library runtime and the model's complete authored phrase corpus are in `riju/local_model.py`; PyInstaller includes both via normal imports. Training data and fitted in-memory model are CC0-1.0; no third-party training corpus or model weights. The runtime follows the repository's code terms. Model version and SHA-256 of canonical phrase data identify each packaged build. Any modified data requires re-running evaluation.

The model uses inverse-class-frequency weighted multinomial Naive Bayes over authored English topic phrases, Laplace smoothing and explicit probability/margin abstention. Its score is an internal classifier score, not a calibrated guarantee of correctness. Deterministic, actor-aware existing revenue interpretation takes precedence where available; statistical classification extends phrases such as premises rental, payroll remuneration and diagnostic apparatus. Account references resolve only against current active masters and service-mode mappings. Subjects outside supported healthcare receipts, eight expense/asset topics and resort receipts need manual review. Non-English, general reasoning, inventory purchases and arbitrary multi-transaction instructions are outside scope.

The extractor supports one positive gross INR amount (including Indian comma grouping and explicit lakh/crore/thousand), one payment method, source reference, optional party, explicit ISO, slash DD/MM/YYYY or named-month date, current branch name or explicit branch code. No relative-date inference. Explicit extracted dates/branches populate the draft fields for review. Missing dates/branches use visible selected values. Ambiguity, negation, conditional transactions, unknown accounts, mixed amounts/methods/services, inactive masters and locked periods stop draft generation. GST/TDS, advances/refunds, construction/retention and asset lifecycle actions route to dedicated reviewed workflows. Outgoing collection-clearing use is refused. Failed interpretation clears any previous language draft so it cannot be accidentally reused.

Evaluation: `tests/test_offline_language.py` has 24 held-out recombinations covering all classifier topics, all 15 established service-mode mappings, party/date/unit/reference extraction, no-network execution, amount scaling, normal posting guards and adversarial abstention/routing. These are synthetic developer tests, not an estimate of customer-language accuracy; target-PC/client examples still need acceptance. The CPU test requires 100 complete interpretations in under five seconds on the CI machine. Packaged Windows self-test records actual time for 100 drafts, model version and digest. Native Windows Actions regression and executable smoke are required, with no accelerator dependency. No lower-bound RAM/CPU claim is inferred from a hosted runner; test the customer's PC before acceptance.
